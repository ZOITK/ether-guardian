# 에테르 가디언 - 프로토타입 개발 설계서 (카메라 영상 처리 & 성능 중심)

---

## 1. 개요 (Overview)

본 설계서는 **AR 기반 실시간 공간 인식**과 **고성능 영상 처리**를 중심으로 프로토타입 개발의 기술적 가능성을 검토합니다.

**핵심 목표:**
- 카메라 영상 입력 → 평면 감지 → 물리 충돌체 생성의 **전체 파이프라인 최적화**
- 모바일 기기에서 **90FPS VR 기준 성능 유지** 또는 **60FPS AR 기준 달성**
- **네트워크 동기화 지연 ≤ 100ms** 유지로 PvP 공정성 보장

---

## 2. 카메라 영상 처리 파이프라인 (Camera Processing Pipeline)

### 2.1 전체 처리 흐름

```
┌─────────────────────────────────────────────────────────────┐
│ 1단계: 카메라 입력 (Camera Input)                          │
│   └─ ARCore/ARKit Raw Frame (YUV420 또는 NV12)             │
│   └─ 입력 해상도: 1920x1080 @ 60FPS (Android)             │
│   └─ 또는 1280x720 @ 30FPS (저사양 기기)                   │
└─────────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ 2단계: 영상 전처리 (Preprocessing)                         │
│   └─ Denoising (노이즈 제거): 2~3ms                        │
│   └─ Histogram Equalization (명도 정규화): 1ms             │
│   └─ Resize to Processing Size (처리용 크기 변환): 1~2ms   │
│   └─ GPU 최적화: NEON (ARM) / SIMD 활용                   │
│   총 처리 시간: ~5ms                                       │
└─────────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ 3단계: ARCore/ARKit 평면 감지 (Plane Detection)            │
│   └─ ARCore의 내장 Feature Extractor                       │
│   └─ 수평면(Floor) 감지: 1~2 프레임 지연 (~30ms)          │
│   └─ 수직면(Wall) 감지: 3~5 프레임 지연 (~80ms)           │
│   └─ 깊이 맵(Depth Map) 생성: 10~15ms                     │
│   └─ LiDAR 활용 (iPhone 12 Pro 이상): 5~8ms               │
│   총 처리 시간: ~15~30ms (LiDAR 없이)                     │
└─────────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ 4단계: 메싱 & 충돌체 생성 (Meshing & Collision)            │
│   └─ Plane Mesh 생성 (삼각형 최적화): 5~10ms               │
│   └─ CollisionShape3D 변환: 3~5ms                         │
│   └─ StaticBody3D에 부착: 1~2ms                           │
│   └─ 메모리 할당 & 인덱싱: 2~3ms                          │
│   총 처리 시간: ~12~20ms                                   │
└─────────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ 5단계: 물리 시뮬레이션 업데이트 (Physics Update)           │
│   └─ Rigidbody 충돌 판정: 3~5ms                           │
│   └─ 몬스터 & 투사체 경로 계산: 5~8ms                      │
│   └─ Occlusion 판정 (벽 뒤 렌더링 스킵): 2~3ms             │
│   총 처리 시간: ~10~16ms                                   │
└─────────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ 6단계: 렌더링 (Rendering)                                  │
│   └─ 카메라 패스스루: 5~8ms                                │
│   └─ AR 오버레이 렌더링 (몬스터, 추출기): 5~10ms           │
│   └─ UI 레이어: 2~3ms                                     │
│   총 처리 시간: ~12~21ms                                   │
└─────────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────────┐
│ 7단계: 네트워크 동기화 (Network Sync)                      │
│   └─ 로컬 상태 패킹: 1~2ms                                 │
│   └─ 서버 전송: ~50~100ms (네트워크 지연)                  │
│   └─ 수신 & 병합: 2~3ms                                   │
│   총 처리 시간: ~55~105ms                                  │
└─────────────────────────────────────────────────────────────┘

────────────────────────────────────────────────────────────────
**전체 프레임 타이밍 (Frame Budget: 60FPS = 16.67ms/frame)**

60FPS 기준:
  영상처리(5ms) + ARCore(15-30ms) + 메싱(12-20ms) + 물리(10-16ms) 
  + 렌더링(12-21ms) = 54-92ms
  ⚠️ 예산 초과 (16.67ms × 4프레임 = 66.67ms 이내)
  
90FPS 기준 (VR):
  프레임당 11.11ms - 위 전체를 실행 불가
  ⚠️ 재설계 필요 (1단계 압축, 멀티스레딩 필수)

→ **현실적인 목표: 60FPS AR 기준, 멀티프레임 처리 (프레임마다 특정 태스크만 업데이트)**
```

### 2.2 성능 최적화 전략

#### A. 멀티스레딩 아키텍처 (Multithreading Architecture)

```gdscript
# 메인 스레드: 렌더링 & UI 전담 (11ms)
├─ 카메라 패스스루 렌더링
├─ AR 오버레이 업데이트
└─ UI 입력 처리

# Worker Thread 1: 영상 처리 + ARCore (병렬 실행)
├─ 카메라 프레임 전처리 (5ms)
├─ ARCore 평면 감지 (15-30ms) - 비동기
└─ 깊이 맵 생성 (10-15ms)

# Worker Thread 2: 메싱 & 물리 (병렬 실행)
├─ 메시 생성 (12-20ms)
├─ 충돌체 생성 (3-5ms)
└─ Rigidbody 업데이트 (10-16ms)

# Worker Thread 3: 네트워크 동기화 (백그라운드)
├─ 로컬 상태 버퍼링
├─ 서버 전송 (비블로킹)
└─ 원격 상태 병합
```

**결과:**
- 메인 스레드: ~11ms (렌더링만) ✓ 60FPS 가능
- 워커 스레드: 동시 처리로 전체 파이프라인 효율화 ✓

#### C. 증분 메싱 (Incremental Meshing)

모든 프레임에 메싱을 하지 않고, **변경이 있을 때만 업데이트**.

```gdscript
# 기존: 매 프레임 모든 평면 리메싱 (비효율적)
# 최적화: 변경된 평면만 업데이트

func _process_plane_update(plane_data):
    # 1. 기존 평면과 비교 (ID, Bounds, Normal 검사)
    var existing_plane = plane_cache.get(plane_data.id)
    
    if existing_plane == null:
        # 신규 평면: 메싱 + 충돌체 생성 (비동기 스레드에서)
        create_mesh_async(plane_data)
    elif plane_data.bounds != existing_plane.bounds:
        # 크기/위치 변경: 기존 메시 수정
        update_mesh_async(plane_data)
    else:
        # 변화 없음: 스킵
        return
    
    plane_cache[plane_data.id] = plane_data
```

**효과:** 메싱 작업 50~70% 감소

### 2.3 ARCore vs ARKit 성능 차이

| 항목 | ARCore (Android) | ARKit (iOS) |
|------|-----------------|-----------|
| 평면 감지 속도 | 2-3 프레임 (30-60ms) | 1-2 프레임 (15-30ms) |
| 깊이 맵 정확도 | 일반 (±5cm) | 높음 (±2cm, LiDAR) |
| 조명 추정 | 구면 조화 함수 | HDR 환경 맵 |
| 메모리 오버헤드 | ~150-200MB | ~100-150MB |
| 배터리 소비 | 높음 (5-7% per 10min) | 중간 (3-5% per 10min) |
| 다중 카메라 지원 | 제한적 | 좋음 (스테레오) |

**전략:**
- **Android**: 멀티스레딩 강화, 해상도 적응
- **iOS**: 네이티브 Metal API 활용, 깊이 정보 적극 활용

### 4.2 고위험 영역 (High-Risk Areas)

#### ⚠️ 1. ARCore 평면 감지 안정성
- **문제**: 조명 부족 환경에서 감지 실패율 20-30%
- **해결**: 보조 깊이 센서 활용, 사용자 피드백 메커니즘
- **영향**: 게임플레이 경험에 직접 영향

#### ⚠️ 2. 네트워크 동기화 지연
- **문제**: 100ms 이상 지연 시 PvP 공정성 저하
- **해결**: 클라이언트 예측(Client-Side Prediction), 서버 권한 구조
- **영향**: 멀티플레이 핵심 기능

#### ⚠️ 3. 메모리 누수 (메싱 시스템)
- **문제**: 평면 생성/삭제 반복 시 메모리 미회수
- **해결**: 객체 풀링, 명시적 리소스 해제
- **영향**: 장시간 플레이 시 프레임 드롭

#### ⚠️ 4. 배터리 소비
- **문제**: 1시간당 배터리 30-40% 소모
- **해결**: 적응형 해상도, 배경 작업 최소화, 화면 밝기 조정
- **영향**: 사용자 경험 (게임 세션 시간 제한)

## 6. 성능 예측 (Performance Projections)

### 현실적인 성능 목표 (Realistic Goals)

| 환경 | 기기 | FPS | 메모리 | 배터리 | 평면 감지 |
|------|------|-----|--------|--------|---------|
| **빈 공간** | Snapdragon 8 | 60 | 250MB | 45분 | >95% |
| **일반 실내** | Snapdragon 8 | 55-60 | 350MB | 40분 | >90% |
| **복잡한 환경** | Snapdragon 8 | 45-50 | 400MB | 35분 | >85% |
| **격렬한 전투** | Snapdragon 8 | 35-40 | 450MB | 30분 | >80% |
| | | | | | |
| **일반 실내** | Snapdragon 6 | 45 | 300MB | 50분 | >85% |
| **복잡한 환경** | Snapdragon 6 | 35-40 | 380MB | 40분 | >80% |
| | | | | | |
| **일반 실내** | Snapdragon 4 | 30 | 200MB | 60분 | >75% |

### 제약 사항 (Constraints)

1. **카메라 처리 지연은 감소 불가**: ARCore/ARKit 자체의 한계
   - 최소 15-30ms (평면 감지)
   
2. **메모리는 기기 RAM에 의존**
   - 6GB RAM 기준 안전 (≤500MB)
   - 4GB RAM 기준 위험 (400-450MB 권장)

3. **배터리는 60FPS 유지 불가**
   - 실제 게임 세션: 30-45분 (충전 필요)
   - 위치 서비스 + AR = 고전력 소비

4. **PvP 지연은 네트워크에 의존**
   - 로컬 Wi-Fi: 20-50ms ✓
   - 5G: 30-70ms ✓
   - 4G LTE: 80-150ms ⚠️
