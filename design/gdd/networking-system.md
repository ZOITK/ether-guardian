# 네트워킹 시스템 (Networking System) — GDD

**게임**: 에테르 가디언  
**시스템**: 멀티플레이 동기화, PvP 상호작용, 실시간 이벤트  
**작성일**: 2026-05-21  
**상태**: 설계 확정

---

## 1. 개요 (Overview)

**네트워킹 시스템**은 게임을 **멀티플레이 경험**으로 만드는 기반입니다. 플레이어의 위치, 영토 점유 상태, 전투 이벤트를 실시간으로 동기화하여 다른 플레이어들과 같은 게임 월드를 공유합니다.

**동기화 범위**:
```
플레이어 위치 (GPS)
    ↓
영토 상태 (점유, 강화, HP)
    ↓
몬스터 AI 상태 (동시 스폰 동기화)
    ↓
전투 이벤트 (투사체 히트, 대미지)
    ↓
실시간 경험 (다른 플레이어와 동시 플레이)
```

---

## 2. 플레이어 판타지 (Player Fantasy)

- **공유된 게임 월드**: 같은 지역에서 다른 플레이어를 보고, 경쟁
- **리얼타임 전쟁**: 내 진지를 침략하는 다른 플레이어와 실시간 대전
- **협력 플레이**: (향후) 몬스터 사냥 협력, 영토 동맹
- **글로벌 리더보드**: 전 세계 플레이어와 자원/영토 경쟁
- **비동기 침략**: 오프라인일 때도 다른 플레이어의 침략을 자동 방어

## 3. 상세 규칙 (Detailed Rules)

### 3.1 플레이어 위치 동기화

**동기화 주기**:
```
위치 업데이트 주기 = 100ms (10 updates/sec)
위치 정확도 = GPS ±5m (실제 GPS 오차)
로컬 보간 = 클라이언트 예측 (마지막 위치 기반 이동)
```

**프로토콜** (Protocol Buffers):
```protobuf
message PlayerPositionUpdate {
    int32 player_id = 1;
    double latitude = 2;       // GPS
    double longitude = 3;      // GPS
    int32 altitude = 4;        // 미터
    float heading = 5;         // 카메라 방향 (0-360)
    int64 timestamp = 6;       // 서버 타임스탐프
}
```

**대역폭 최적화**:
```
패킷 크기: 32 bytes (고정)
플레이어당 대역폭: 32 × 10 updates/sec = 320 bytes/sec
100 플레이어: 32 KB/sec = 256 Kbps (4G LTE 충분)
```

### 3.2 영토 상태 동기화

**동기화 항목**:
```protobuf
message TerritoryState {
    int32 territory_id = 1;
    int32 owner_id = 2;
    double latitude = 3;
    double longitude = 4;
    int32 current_hp = 5;
    int32 max_hp = 6;
    repeated TurretInfo turrets = 7;
    int32 ether_stored = 8;
    int64 last_updated = 9;
}

message TurretInfo {
    int32 turret_id = 1;
    float relative_x = 2;
    float relative_y = 3;
    int32 current_hp = 4;
    bool is_active = 5;
}
```

**동기화 전략**:
- **변경 기반**: 상태 변경 시만 전송 (즉시)
- **주기 기반**: 미변경 시 5초마다 확인 (동기화 확보)
- **로컬 캐시**: 클라이언트에서 영토 상태 로컬 캐시 (오프라인 모드)

### 3.3 전투 이벤트 (Combat Events)

**이벤트 종류**:

```protobuf
enum CombatEventType {
    PROJECTILE_FIRED = 0;      // 투사체 발사
    PROJECTILE_HIT = 1;         // 투사체 히트
    MONSTER_SPAWNED = 2;        // 몬스터 스폰
    MONSTER_KILLED = 3;         // 몬스터 제거
    TERRITORY_DAMAGED = 4;      // 진지 피해
    TERRITORY_DESTROYED = 5;    // 진지 파괴
}

message CombatEvent {
    int32 event_id = 1;
    CombatEventType type = 2;
    int32 initiator_player_id = 3;
    int32 target_player_id = 4;  // 선택사항
    float x = 5;
    float y = 6;
    float z = 7;
    int32 damage = 8;            // 선택사항
    int64 timestamp = 9;
}
```

**서버 검증**:
```
클라이언트: 투사체 히트 보고
    ↓
서버: 
  1. 투사체 궤적 역계산 (부정행위 감지)
  2. 거리 범위 확인 (100m 이상 = 스킵)
  3. 대미지 재계산 (클라이언트 값 검증)
    ↓
서버: 최종 대미지 적용 & 브로드캐스트
```

### 3.4 침략 & 방어 이벤트 (Invasion)

**침략 흐름**:

```
1. 침입자 진입 감지 (300m 이내)
   └─ 서버 플레이어 거리 확인

2. 진지 근접 (100m 이내)
   ├─ 방어자에게 알림 발송
   └─ 서버: 전투 모드 활성화

3. 전투 진행
   ├─ 침입자: 터렛 피해 받음
   ├─ 방어자: 온라인이면 터렛 자동 발동
   ├─ 방어자: 오프라인이면 AI 터렛만 작동
   └─ 서버: 모든 이벤트 기록

4. 전투 종료
   ├─ [침입자 승리] → 진지 파괴, 에테르 약탈
   ├─ [방어 승리] → 침입자 추방, 방어 포인트 획득
   └─ 서버: 최종 상태 동기화
```

**네트워킹 메시지**:
```protobuf
message InvasionEvent {
    int32 invader_id = 1;
    int32 defender_id = 2;
    int32 territory_id = 3;
    enum Result {
        ONGOING = 0;
        INVADER_WON = 1;
        DEFENDER_WON = 2;
    }
    Result result = 4;
    int32 ether_looted = 5;     // 약탈량
    int64 started_at = 6;
    int64 ended_at = 7;
}
```

### 3.5 오프라인 모드 (Offline Mode)

**조건**:
- 네트워크 연결 없음
- 자동 감지: 서버 재연결 실패 후 3초 경과

**기능**:
```
온라인 기능:
  ✅ 플레이어 위치 표시 (X)
  ✅ 다른 진지 표시 (로컬 캐시만)
  ✅ 몬스터 사냥 (로컬, 동기화 안함)
  ✅ 진지 강화 (로컬, 재연결 후 동기화)
  ✅ 자동 방어 (터렛만, 명령어 안함)

오프라인 기능:
  ❌ 침략 (네트워크 필요)
  ❌ 플레이어 간 상호작용
  ❌ 리더보드 확인

재연결 시:
  1. 로컬 변경사항 병합 (충돌 해결)
  2. 서버 상태 확인
  3. 불일치 시 조정 (서버 권한)
```

**로컬 데이터 저장** (JSON):
```json
{
  "local_changes": {
    "position": {"lat": 37.123, "lon": 126.456},
    "actions": [
      {"type": "monster_killed", "count": 3},
      {"type": "upgrade_turret", "cost": 500}
    ]
  },
  "last_sync": "2026-05-21T12:00:00Z",
  "sync_queue": [...]
}
```

### 3.6 플레이어 가시성 (Visibility)

**가시 범위**:
```
1km 반경 내 플레이어: 지도에 표시
1km ~ 5km: 존재 표시 (실시간 위치 X)
5km 이상: 미표시
```

**감지 지연**:
```
로컬 변경: 즉시
근처 플레이어 업데이트: 1초 (10 updates/sec)
원격 플레이어 업데이트: 5초 (2 updates/sec, 대역폭 절감)
```

## 4. 공식과 균형 (Formulas)

### 4.1 네트워크 지연 보상

```
클라이언트_예측_위치 = 마지막_위치 + (속도 × 지연시간)
                = P(t) + (V × RTT/2)

예시:
마지막 수신: P = (37.0, 126.0)
플레이어 속도: V = 5 m/s (달리기)
RTT = 100ms

예측: P + (5 × 0.05) = (37.0, 126.0) + 0.25m
```

### 4.2 서버 부하 추정

```
메시지/초 = 플레이어_수 × (위치_업데이트 + 이벤트)
         = N × (10 + 0.5)
         
예시:
100 플레이어: 100 × 10.5 = 1050 msg/sec
1000 플레이어: 1000 × 10.5 = 10,500 msg/sec (스케일 필요)
```

### 4.3 에테르 약탈 공식

```
약탈_에테르 = 진지_저장_에테르 × 약탈률

기본: 50%
최소: 500 에테르 (약탈 최소값)
최대: 5000 에테르 (약탈 최대값)
```

## 5. 엣지 케이스 (Edge Cases)

| 상황 | 처리 |
|------|------|
| 동시 침략 (A vs B, B vs C) | 먼저 온 침략자 우선 처리 |
| 네트워크 지연 (>500ms) | 경고 표시, 로컬 모드 전환 권유 |
| 부정행위 감지 (불가능한 히트) | 히트 무시, 플레이어 기록 |
| 서버 다운 | 로컬 모드 자동 전환, 재연결 폴링 |
| 플레이어 위치 이상 (텔레포트) | GPS 점프 감지, 이전 위치로 복구 |
| 동시 진지 강화 (A, B 각각) | 순서대로 처리, 마지막 상태 유지 |
| 플레이어 중복 접속 | 기존 세션 종료, 새 세션 시작 |

## 6. 의존성 (Dependencies)

- **영토 시스템**: 진지 위치, 상태 동기화
- **전투 시스템**: 투사체 히트 이벤트, 몬스터 스폰
- **GPS/위치 서비스**: 플레이어 좌표 제공
- **Go 백엔드**: TCP 소켓 서버 (실시간 메시지 브로드캐스트)
- **데이터베이스**: PostgreSQL (영토 영구 저장), Redis (캐시)

| 파라미터 | 기본값 | 범위 | 영향 |

## 8. 수용 기준 (Acceptance Criteria)

### 기능
- ✅ 플레이어 위치 실시간 동기화 (<100ms RTT)
- ✅ 영토 상태 동기화 (변경 시 즉시)
- ✅ 전투 이벤트 실시간 브로드캐스트
- ✅ 침략 시스템 완동작 (시작 → 종료)
- ✅ 오프라인 모드 자동 전환 & 재연결

### 성능
- ✅ 100 플레이어 동시 접속 시 1000 msg/sec 처리
- ✅ 패킷 손실률 <2%
- ✅ 평균 지연 <100ms
- ✅ 메모리 오버헤드 <100MB (서버)

### 보안
- ✅ 투사체 히트 서버 검증 (부정행위 방지)
- ✅ GPS 스푸핑 감지 (불가능한 이동 거리)
- ✅ 인증 토큰 기반 연결
- ✅ 방어자 오프라인 시에도 터렛 자동 방어

### 테스트
- ✅ 50 플레이 세션 (네트워크 안정성)
- ✅ 침략 10회 이상 (PvP 메커니즘)
- ✅ 오프라인 모드 테스트 (재연결 병합)

## 10. 네트워크 토폴로지

```
┌─────────────────────────────────────────────┐
│ 클라이언트 (모바일)                         │

         ↓ (SQL)              ↓ (Redis)
   ┌──────────────┐     ┌──────────────┐
   │ PostgreSQL   │     │    Redis     │
   │ (영토 저장)  │     │  (캐시, 세션) │
   └──────────────┘     └──────────────┘
```

## 11. 대역폭 추정

**전형적 게임 세션** (100 플레이어, 30분):

```
플레이어 위치: 100 × 10 updates/sec × 32 bytes × 60 sec × 30 min
           = 576 MB/hour

영토 상태: 100 영토 × 2 updates/sec × 100 bytes × 3600 sec
        = 72 MB/hour

전투 이벤트: 평균 500 events/hour × 80 bytes
           = 40 KB/hour

총합: ~650 MB/hour (또는 1.5 Mbps 평균)
```
