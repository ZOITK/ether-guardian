## 1. 개요 (Overview)

**비전 시스템**은 게임의 **핵심 기반 시스템(Foundation)**입니다. 모바일 카메라 영상을 실시간으로 분석하여 현실 공간의 평면(바닥, 벽)을 감지하고 3D 메싱으로 변환합니다. 이를 통해 게임 월드를 현실 공간에 정확히 배치할 수 있습니다.

**역할**:
- 실시간 AR 카메라 입력 처리
- 평면 감지 및 깊이 맵 생성
- 충돌 메시 생성 (StaticBody3D)
- 오클루전 처리 (벽 뒤 렌더링 최적화)

---

## 2. 플레이어 판타지 (Player Fantasy)

- **현실과 가상의 경계 해제**: 현실 공간에 몬스터와 진지가 실제로 존재하는 느낌
- **공간 활용의 자유도**: 자신의 집, 사무실, 공원 어디든 게임 플레이 가능
- **물리적 현실감**: 벽 뒤에 몬스터가 숨으면 실제로 보이지 않음
- **정확한 조준**: 카메라 기울기와 실제 공간이 동기화된 사격

## 3. 상세 설계 (Detailed Design)

### 3.1 처리 파이프라인

```
┌─────────────────────────────────────────────┐
│ 1단계: 카메라 입력 (Camera Input)          │
│  - ARCore/ARKit Raw Frame (YUV420/NV12)   │
│  - 입력 해상도: 1920×1080 @ 60FPS         │
│    (또는 1280×720 @ 30FPS 저사양 기기)    │
└─────────────────────────────────────────────┘
                    ↓ (5ms)
┌─────────────────────────────────────────────┐
│ 2단계: 전처리 (Preprocessing)              │
│  - OpenCV 활용 (GDExtension C++)           │
│  - 노이즈 제거 (Bilateral Filter)          │
│  - 명도 정규화 (CLAHE)                     │
│  - 처리 크기 변환 (960×540)                │
│  - 총 처리: ~5ms                           │
└─────────────────────────────────────────────┘
                    ↓ (15-30ms)
┌─────────────────────────────────────────────┐
│ 3단계: 평면 감지 (Plane Detection)         │
│  - ARCore/ARKit 네이티브 호출               │
│  - 수평면(Floor) 감지: 1-2 프레임 (~30ms) │
│  - 수직면(Wall) 감지: 3-5 프레임 (~80ms)  │
│  - 깊이 맵 생성: 10-15ms                   │
│  - 총 처리: ~15-30ms                       │
└─────────────────────────────────────────────┘
                    ↓ (12-20ms)
┌─────────────────────────────────────────────┐
│ 4단계: 메싱 & 충돌체 생성                  │
│  (Meshing & Collision)                      │
│  - 평면 Mesh 삼각형 최적화: 5-10ms        │
│  - CollisionShape3D 변환: 3-5ms            │
│  - StaticBody3D 부착: 1-2ms                │
│  - 총 처리: ~12-20ms                       │
└─────────────────────────────────────────────┘
                    ↓ (2-3ms)
┌─────────────────────────────────────────────┐
│ 5단계: 물리 업데이트 (Physics)             │
│  - Rigidbody 충돌 판정: 3-5ms             │
│  - 몬스터 경로 계산: 5-8ms                 │
│  - 오클루전 판정: 2-3ms                    │
│  - 총 처리: ~10-16ms                       │
└─────────────────────────────────────────────┘
                    ↓ (12-21ms)
┌─────────────────────────────────────────────┐
│ 6단계: 렌더링 (Rendering)                  │
│  - 카메라 패스스루: 5-8ms                  │
│  - AR 오버레이: 5-10ms                     │
│  - UI/HUD: 2-3ms                           │
│  - 총 처리: ~12-21ms                       │
└─────────────────────────────────────────────┘
```

### 3.2 GDExtension C++ 모듈 설계

**목적**: 영상 전처리 + OpenCV 통합으로 성능 +30% 향상

**구조**:
```
GDExtension (C++11)
├── VisionProcessor
│   ├── preprocess_frame() — OpenCV 노이즈 제거, 정규화
│   ├── detect_features() — 엣지 감지 (선택사항)
│   └── process_depth_map() — 깊이맵 후처리
├── ARManager (네이티브 플러그인 래퍼)
│   ├── initialize_arcore() / initialize_arkit()
│   ├── get_planes() — 감지된 평면 배열 반환
│   └── get_depth_data() — 깊이맵 데이터 반환
└── PerformanceMonitor
    ├── measure_frame_time()
    └── log_pipeline_stats()
```

**OpenCV 의존성**:
```cmake
# CMakeLists.txt (GDExtension 빌드)
find_package(OpenCV 4.5 REQUIRED)
target_link_libraries(vision_processor ${OpenCV_LIBS})
```

### 3.3 ARCore vs ARKit 전략

| 항목 | ARCore (Android) | ARKit (iOS) | 전략 |
|------|-----------------|-----------|------|
| **평면 감지 속도** | 2-3 프레임 (30-60ms) | 1-2 프레임 (15-30ms) | iOS 우선 사용, Android는 적응형 FPS |
| **깊이 정확도** | ±5cm | ±2cm (LiDAR) | 조명 부족 시 보조 깊이 센서 활용 |
| **조명 추정** | 구면 조화 함수 | HDR 환경맵 | ARKit 신뢰도 높음 |
| **메모리 오버헤드** | ~150-200MB | ~100-150MB | 기기 RAM 예약 필요 |
| **배터리** | 높음 (5-7%/10min) | 중간 (3-5%/10min) | 배경 작업 최소화 |

**통합 전략**:
```gdscript
# ar_manager.gd
func _ready():
    if OS.get_name() == "iOS":
        ar_backend = ARKitBridge.new()
    else:
        ar_backend = ARCoreBridge.new()
    ar_backend.initialize()
```

## 4. 엣지 케이스 (Edge Cases)

| 상황 | 처리 |
|------|------|
| **조명 부족** (야간, 실내 어두운 곳) | ARCore 감지 실패율 20-30% → 사용자 피드백 요청 |
| **빠른 카메라 이동** | 평면 감지 지연 증가 → 안내 ("천천히 움직이세요") |
| **반사 표면** (거울, 유리) | 감지 불안정 → 필터링 (정상 벡터 검증) |
| **매우 작은 공간** (<2m²) | 게임 플레이 불가 → 영역 확인 대화 |
| **네트워크 없는 실내** | 위치 서비스 불가 → 로컬 모드 (오프라인 PvE) |

## 5. 의존성 (Dependencies)

- **플랫폼 SDK**: ARCore (Android API 26+), ARKit (iOS 14.3+)
- **OpenCV**: 4.5+ (C++ GDExtension 빌드)
- **물리 엔진**: Godot 4.6 Jolt Physics
- **네트워크**: Go 소켓 서버 (위치 데이터 동기화)
- **GPS/위치**: 지오스페이셜 API (영토 점유 기록)

## 6. 튜닝 노브 (Tuning Knobs)

| 파라미터 | 기본값 | 범위 | 영향 |
|---------|-------|------|------|
| 평면 감지 업데이트 간격 | 매 프레임 | 1-5 프레임 | 성능 vs 반응성 |
| 메싱 삼각형 세분화 | 중간 | 낮음-높음 | 정확도 vs 메모리 |
| 깊이맵 후처리 필터 강도 | 3 | 1-5 | 노이즈 제거 vs 디테일 |
| 카메라 FOV | 기본 (55°) | 45-90° | 시야각 |
| 오클루전 활성화 | ON | ON/OFF | 렌더링 성능 |

## 7. 수용 기준 (Acceptance Criteria)

- ✅ ARCore/ARKit 기본 평면 감지 구현

- ✅ 평면 감지 지연 <50ms
- ✅ 메싱 생성 성능 <20ms
- ✅ 메모리 사용량 <500MB
- ✅ 60FPS 유지 (고성능 기기)
- ✅ 45FPS 이상 (복잡한 환경)
- ✅ GDExtension C++ 모듈 통합 테스트 완료
- ✅ OpenCV 기능 (전처리, 노이즈 제거) 활성화
